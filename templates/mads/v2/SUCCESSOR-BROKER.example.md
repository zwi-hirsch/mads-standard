# Automatic successor broker (v2.0.7 candidate)

Only a trusted launcher and Owner-controlled broker may use this protocol. The agent cannot authenticate its own launch. The reference CLI uses a canonical local bare SHA-1 repository and an SSH allowed-signers file outside agent-writable Git. Never use it on a noncanonical mirror.

- Install trusted policy and signer allowlist out of band; authenticate the human replacement event and exact successor ACK; retain authenticated requests and receipts in an independently protected audit store.
- Enroll one role with immutable canonical repo path, role-current pointer, epoch status prefix, source prefix, inbox/outbox, all required main/global mailbox guards, lock paths, the exact supported status schema (status_schema), the exact approved monitoring_mode (manual, OWNER_EXPLICIT_BOUNDED_MANUAL_EXCEPTION or WATCHDOG_VERIFIED), canonical ledger_ref and ledger_path, and the independently approved allowed_paths (literal files or directory/**). Missing or unknown schema/scope blocks admission. Bootstrap current pointer to the exact live status; all later status writers update pointer and epoch together. Verify full inherited ledger (all task IDs/reserves/reviews/evidence) and STOP/SECURITY independently before signing.
- Offer request includes project, role, kind=offer, directive=HUMAN_REPLACEMENT, conflict=false, stop_reviewed=true, ledger_reviewed=true, unique 32-hex id, issued_at/expires_at (max 15 minutes), current_tip, old_session, source_head/tree, lock_blobs, guards map including outbox, inbox_tip, ledger_ref/path/sha256. Sign exact bytes under namespace mads.successor.v1. Broker verifies signature and atomically publishes revoked old status, STOP, new conditional offer and isolated source branch.
- Successor independently reads old revoke, exact offer and inherited ledger, then writes the exact ACK JSON described in scripts/successor_broker.py. Authenticated launcher verifies actual successor identity and ACK, rechecks all refs and signs kind=activate with fresh request id and offer_id plus the same old_session and ledger tuple as the offer. Each request has exactly the documented fields for its kind; additional fields are denied. IDs are unique across kinds for a project role and an immutable request-kind/digest record is appended atomically in its inbox. Exact retry is allowed only for the current transaction without drift. Predecessor lock_blobs must already equal the requested complete lock map. Broker verifies and atomically activates.
- If a request is replayed after drift, or old source moves, freeze and reconcile rather than issuing another epoch. No automatic renewal or scope expansion.
- Run `python3 scripts/test_successor_broker.py` in a clean source checkout. Test fixtures use temporary bare repositories and call the authenticated transaction core directly; malformed CLI JSON is checked separately. They do not prove real launcher integration, valid signature CLI end-to-end, remote atomic transactions, protected refs or strong fencing. The JSON parser rejects non-object, duplicate and nonfinite inputs; the role schema and scope are checked against protected enrollment. Existing policy without these fields MUST remain disabled until independently migrated.
- CLI: `python3 scripts/successor_broker.py --repo <canonical-bare> --policy <trusted-json> --request <signed-json> --signature <signature-file> --allowed-signers <trusted-allowlist>`. Only the trusted broker operator invokes this command. Do not run in agent-controlled execution context.
- The reference broker rechecks direct commit refs while Git holds prepared transaction locks; raw privileged filesystem/ref mutation outside Git is not protected. Deployment requires enforced canonical writer isolation, including denial of direct raw writes; otherwise keep it disabled.
- For FULL/DELTA recovery retain an independently protected complete ref-name/type/OID manifest, including refs whose tips are already in the prerequisite history. Verify prerequisite/source objects and strict fsck, reconstruct missing refs via expected-old CAS only, reject unexpected/conflicting/symbolic refs, verify all final refs against the manifest. A delta bundle alone is not a complete ref inventory; perform a fresh independent restore before acceptance.
- If any deployment/identity/atomicity gate is missing, use §29 Owner manual recovery. No background wake, production, host or merge authority.
